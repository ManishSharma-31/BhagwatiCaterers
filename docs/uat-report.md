# UAT report: Bhagwati Caterers website and admin portal

Date: 2026-11-27. Build under test: `apps/site` (`npm run build`, 42 public pages + /admin/). Served from `dist` with `python3 -m http.server 8771`. Playwright (Python) with system Chrome, 390x800 and 1280x800. All `wa.me` traffic was intercepted (route fulfilled locally, and host mapped to 127.0.0.1), so nothing left the machine. Admin was run with `localStorage bc:local-only=1`. Review only: no source files were edited, no git commands run. Test scripts are in `/tmp/uat/*.py` (not part of the repo).

## 1. Summary

| Result | Count | User stories |

No blocker or critical defect found. 0 console errors, 0 page errors, 0 failed/4xx requests, 0 broken images, 0 horizontal overflow across all 84 page/viewport combinations (42 pages x 2 viewports) and across 15 admin routes at both widths. 17 defects logged: 0 high, 7 medium, 10 low.

## 4. What could not be tested

- Cloud/Supabase login, sync, sign-out with pending changes, "denied" state: no network. A fresh browser without `bc:local-only` shows the cloud login form (email/password, Marathi) and that is all that could be verified.
- Real WhatsApp delivery, `tel:` dialing, Google Maps and the Wikimedia/Pexels credit links (external, not fetched).
- Real-device behaviour: iOS Safari popup blocking (D5 is derived from code plus the observed static href), native date pickers, PWA/install, real mobile print/PDF dialog (only print-media emulation and Chrome PDF export were used).
- Real 3G/4G timing and host compression/CDN headers (lab throttling on a plain Python server only; no Lighthouse run).
- Screen reader testing and zoom/large font settings; Hindi admin (admin offers only Marathi/English).
- Time-based behaviour: the 30-second PIN lockout expiry (simulated by clearing the lock key), date-change rollovers.
- Multi-device cloud conflict handling.

## 5. Top 10 fixes (in order)

1. D1/D2: validate event date (not in the past) and guests (whole number, sane max) in the quote form.
2. D5: make the "Open WhatsApp" fallback button carry the composed message (popup-blocked users currently lose everything).
3. D4: shrink menu thumbnails / lazy-load / preload the cart script so the 603-dish menu is tappable fast on slow phones; enable compression on the host.
4. D7: replace the placeholder domain before launch (canonical, hreflang, sitemap, OG, JSON-LD).
5. D6: remove the "owner should have this policy reviewed by an advocate" note from the public legal pages (or get the review done first).
6. D3: stop the starter menu duplicating after Clear + Merge restore (stable ids or dedupe).
7. D8: confirm the public business email with the owner.
8. D13: add a branded 404 page.
9. D9/D11: enlarge footer link tap targets and disambiguate the "Menu" toggle label.
10. D15/D14: payments form route handling and amount sanity limit.
